# 広告クローザー（試作 v0.7）

セルサバイバー（`defense.roguelike.cell.shoot.survivor`）専用、自分用のAndroidアプリです。
報酬広告を最後まで再生し、終わったら×ボタンを自動で押して閉じます。広告ボタンを押すのは人間側です。

## 対応パターン（2026-11-11 の実機スクリーンショットから確定）

- **A**: 「報酬を獲得しました ✕」が出る（×は約 94%, 6%）。文字を検知して押す。
  英語版カード（「Reward granted」）も同じ判定で、ピルが左上に出る型（「✕ Reward granted」、
  ×は約 5.5%, 4.6%）もあるため、テキストの実位置で左右を判定する。×の高さは 6.1% と 4.6% を交互に試す
- **B**: ×が左上（約 6%, 6% / 6%, 3%）、報酬文字なし。広告開始から設定秒数（初期値30秒）過ぎてから押す
- **C**: 左上のGoogle Playリンクを踏む必要がある型。リンクを押すとPlayアプリが全画面で開くので、
  ゲームの起動インテントで直接呼び戻し（失敗時のみ履歴の中央カードを1回タップ）、その後に出る×を押す
- **D**: 左上に「閉じる」と書かれたピル型ボタンだけがある型（約 10%, 6%）。報酬文字も
  インストール文字もない。ラベルの実位置をそのままタップする（左上の隅にある場合のみ。
  ゲーム内ダイアログの「閉じる」は中央付近なので誤爆しない）
- **ストアのシート**: 広告の上にPlayのシートが開く（勝手に開くこともある）。シートの×（約 93%, 23%）で閉じて広告に戻る

安全設計: 押すのは上記の隅の座標だけ。中央の「インストール／開く」は絶対に押さない。
ストア処理は広告の監視中だけ。想定外が続く場合は自動で止まり、ログに残る。

## インストール後の設定

1. アプリ「広告クローザー」を開く
2. 「① ユーザー補助の設定を開く」→「広告クローザー」をオン
3. 「② ほかのアプリの上に表示する許可」をオン
4. 「フローティングボタンの表示／非表示」でボタンを出す（手動開始用。任意）
5. セルサバイバーで普通に広告を見る

## ビルド

GitHub Actions（`.github/workflows/build-apk.yml`）が `main` への push で
デバッグAPKをビルドし、リリースに `app-debug.apk` を添付します。
スマホからはリリースページからAPKをダウンロードしてインストールできます
（提供元不明アプリの許可が必要）。

## 既知の限界

- 動画広告の再生中は画面に特徴的な文字がないため、開始検知は
  エンドカード表示か広告用アクティビティの出現に頼ります。
  検知できない広告では、フローティングボタンの「広告開始」を押してください
- （v0.5で解消）フローティングボタンは「≡ 移動」部分を掴んでドラッグ移動でき、
  位置は保存される。右上の ✕ で消せて、履歴からアプリを消す（タスクキル）と連動して消える

## 署名について（v0.3〜）

CI は実行のたびに新しいマシンで走るため、そのままではデバッグ署名が毎回変わり、
Android に「既存のパッケージと競合する」と言われて上書き更新できませんでした
（v0.2 のインストール時に実際に発生）。v0.3 からは、プロジェクト固定の署名鍵
（標準の Android デバッグ鍵の形式。`debug-keystore.b64` をビルド時に復号して使用）
で毎回署名するので、今後は上書きインストールで更新できます。
なお v0.3 自体は署名が変わるため、v0.1/v0.2 からの移行時だけ一度アンインストールが必要です。

## v0.2 での修正（実機ログ 2026-11-11 に基づく）

- v0.1 は全画面ストアからの復帰で、履歴画面の「セルサバイバー」という
  アプリ名ラベルを約0.7秒ごとにタップし続けていた。One UI ではラベル部分の
  タップは無効なため約40回空振りし、ユーザーが履歴画面に置き去りになった。
- v0.2 は起動インテントでゲームを直接前面化する方式を主とし、履歴は
  「開く→中央カードを1回だけタップ」の予備手段に変更。各手順は1回だけ実行し、
  駄目なら無限リトライせずログに残して手動復帰を促す

## v0.8 周回モード（2026-11-12 追加）

低レベルステージ周回の補助。ユーザーの実機スクショで設計した、色（ピクセル）
ベースの画面判別で、ユーザー補助のスクリーンショット機能を使う（要 Android 11+、
色ビットマップ化のため実質 Android 12+）。

- ステータス強化（3枚＋無料リフレッシュボタンあり）：
  カード色をサンプリングし 赤>黄>紫>青>緑 の最強を選択。同色タイは真ん中→左→右
- ルーレット結果（2枚・ボタンなし）：「空白をタップして続ける」位置をタップ
- ルーレット：緑の「確認」のみ（オレンジの AD リフレッシュは押さない）
- 勝利：緑の「確認」のみ（青の AD「2倍受け取る」は押さない）
- 戦闘中・ステージ選択画面では何も押さない（バトル開始は手動。スタミナ節約のため）
- 切り替えはメイン画面のスイッチとフローティングボタンの両方から。
  フローティングの「停止」は「全停止」に改名し、周回も広告閉じも止める
- 同じ画面への対処が1分以内に3回を超えたら周回モードは自動停止してログに残す
- 広告セッション中は周回判定を休止し、広告閉じを優先する

## v1.5 パターンE（2026-11-12 追加）

TikTok（Pangle系）エンドカード。「Google Playに行く」ボタンが目印で、×が無い。
右上の制御は最初「>>」で、押すと広告主アプリ（TikTok）が全画面で開く。
アプリ切り替えでゲームに戻ると、同じ右上（92.6%, 7.2%）が×に変わっている
（ユーザーの実機スクショ3枚で確認した流れを自動化）。

- 検知後、待ち時間（ガード秒数）が過ぎてから右上の「>>」をタップ
- 別アプリに移ったら、起動インテントでゲームを呼び戻す（パターンCと同方式、最大3回）
- 戻ったら右上の×をタップ（最大3回）
- 別アプリが開かなかった場合は、そのまま右上を×として試す
- 遷移先アプリ（TikTok等）を見えるようにするため、ユーザー補助の
  対象パッケージ制限を外した（v1.5のインストール後はユーザー補助の
  オフ→オンが一度必要）。アプリ側の動作は従来通り、セッション中に対象
  パッケージでしかタップしない

## v1.6 周回ボタン対策（2026-11-12 追加）

v1.4 実機テストで、ルーレットと勝利（バトルリザルト）の「確認」タップが
ログに残るのにゲームが進まない症状が残った（リザルトの空白タップも
2回要した例あり）。カード選択の単発タップは安定している。

- 確認系ボタン（勝利／ルーレット／空白タップ）を「400ms間隔の
  ダブルタップ（1ジェスチャで2回押し）」に変更。カード選択は従来通り
- 全タップにジェスチャ結果コールバックを追加し、キャンセルされた場合は
  ログに残す（アプリ側でジェスチャが失われたのか、ゲーム側が無視した
  のかを切り分けられるように）
- 周回のタップ後クールダウンを 3秒→4.5秒 に延長

## v1.9 パターンF再修正（2026-11-12、ユーザー指摘・重要）

v1.8 の定期タップ方式は危険だったため破棄（v1.8 はインストールしないこと）。
ユーザー指摘：メーターが終わる前に右上を押すと Google Play へ移動してしまう。

## v2.1 オートクリッカー（2026-11-12、ユーザー要望）

汎用の自動連打機能を追加（広告セッションとは独立、どのアプリの上でも動く）。

- フローティングパネルに「連打の場所指定」と「連打開始／連打終了」を追加
- 「連打の場所指定」でマト（◎グラフィック）が出る。ドラッグで中心を
  合わせると位置が保存される
- 連打中はマトをタッチ素通し＋半透明に切り替える（マト自身がタップを
  受けてしまうと連打が届かないため）。パネルを閉じると連打も止まる
- メイン画面で細かい設定：指定方法（回/秒 1〜20 ／ 間隔 50〜3000ms）、
  間隔のゆらぎ（±0〜50% ランダム）、自動停止タイマー（0=なし〜60分）
- 連打エンジンはアクセシビリティ側で駆動。個別タップはログに残さない
  （80行ログが数秒で埋まるため）。開始・終了・自動停止だけ記録する
- 全停止ボタンでも連打は止まる

## v2.3 パターンH：Temuファンネル（2026-11-12、ユーザーが手順を実演）

Temu広告は3段構えで、×を押すだけでは終わらない：
1. 広告クリエイティブ（"Main Product" 表記）の右上×（92.7%, 6.4%）
   → Temuのランディングページが広告内に開く
2. ランディングページの右上×（95.8%, 4.1%）→ Temuアプリが起動する
3. ゲームに戻ると黒い終了カード（"Temu: Shop Like a Billionaire"＋
   「開く」）が待っていて、その右上×でようやく広告が終わる

v2.2 は3画面すべて未対応で、最初の画面で「信号なし4秒」となり
セッション自体が終了していた（そのため離脱復帰も働かなかった）。
v2.3 は各画面を広告信号として扱いセッションを維持し、順に×を押す。
2→3 の間のTemuアプリ起動は、汎用化した離脱復帰（起動インテントで
対象アプリへ戻る）が担当する。離脱復帰のログ文言から「パターンE」の
冠も外した。

## v2.6 ルーレット修正＋ジェスチャ競合の解消（2026-11-12、ユーザー指摘とログ）

- ルーレット：スキップのチェックボックスを絶対に押さないよう変更。
  v1.3 の「先にスキップをオン」ロジックは誤りだった（ユーザー訂正）。
  進めるのは下の「確認」ボタンだけ。rou-skip フィンガープリントも廃止
- ログに「タップがキャンセルされました」が連発していた原因は、
  連打（オートクリッカー）と周回のタップの競合。同時に走らせると
  後から出たジェスチャが先のをキャンセルする（特に2打式の確認タップは
  約0.5秒にわたるため連打に潰されていた）。対策として、周回／広告側の
  ジェスチャ実行中は連打がその拍を休むガード（gestureGuardUntil）を導入

## v2.7 パネルの誤爆防止＋カード選択の詰まり対策（2026-11-12、ユーザー報告）

- 「パネルのボタンが勝手に押される」の原因は自前の注入タップ：
  タップは一番上のウィンドウに届くため、パネルがタップ先に重なると
  ゲームではなくパネルのボタンを押していた。対策として
  ・オーバーレイがパネルの矩形を公開し、サービスの全タップ
    （広告／周回／連打）が矩形内なら発射を中止する
  ・重なっていたらパネルが自動で反対側の隅へ退避する
  ・連打開始時、マトがパネルの下にあれば先にパネルを退避する
  パネル自体をタッチ無効化する案は、非常停止ボタンまで押せなく
  なるため採らない
- カード選択の詰まり（ログ 18:27〜18:28）：同じ色並びの画面が
  続くと「同じ画面が進まない」と誤認して休止していた疑いと、
  (82%, 45%) の一点押しの弱さに対し、
  ・フィンガープリントにカードのアイコン署名（アイコン部の
    平均色バケット）を追加し、別アイテムの画面を区別する
  ・リトライごとにタップ位置をずらす（45% → アイコン中心
    37.5% → 52%）。勝利画面で実績のある方式

## v2.8 「閉じたと誤判断」対策＋最終手段（2026-11-12、ユーザーのログ）

ルーレット（ラッキーホイール）広告で、セッション開始と同秒に
パターンDが左上の「閉じる」を押し、そのラベルが消えると4秒で
「広告が閉じた」と誤判断して待機に戻っていた（広告は残ったまま）。

- パターンDに待ち時間：ガード秒経過、またはラベルが8秒
  連続で存在してから押す（初期の閉じる表示は無効／おとりの
  ことがある）
- 「Go」ボタンのみのプレイアブル広告は信号がほぼ無いため、
  "Go" を監視継続の信号として扱う（押す対象にはしない）
- 最終手段フィニッシャー：セッションが50秒続き、どの処理も
  10秒押していない場合、右上の×候補3点を順に試す。再生中
  メーター（0〜0.99）がある間は押さない
