# 広告クローザー（試作 v0.7）

セルサバイバー（`defense.roguelike.cell.shoot.survivor`）専用、自分用のAndroidアプリです。
報酬広告を最後まで再生し、終わったら×ボタンを自動で押して閉じます。広告ボタンを押すのは人間側です。

## 対応パターン（2026-11-11 の実機スクリーンショットから確定）

- **A**: 「報酬を獲得しました ✕」が出る（×は約 94%, 6%）。文字を検知して押す。
  英語版カード（「Reward granted」）も同じ判定で、ピルが左上に出る型（「✕ Reward granted」、
  ×は約 5.5%, 4.6%）もあるため、テキストの実位置で左右を判定する。×の高さは 6.1% と 4.6% を交互に試す
- **B**: ×が左上（約 6%, 6% / 6%, 3%）、報酬文字なし。広告開始から設定秒数（初期値30秒）過ぎてから押す
- **C**: 左上のGoogle Playリンクを踏む必要がある型。リンクを押すとPlayアプリが全画面で開くので、
  ゲームの起動インテントで直接呼び戻し（失敗時のみ履歴の中央カードを1回タップ）、その後に出る×を押す
- **D**: 左上に「閉じる」と書かれたピル型ボタンだけがある型（約 10%, 6%）。報酬文字も
  インストール文字もない。ラベルの実位置をそのままタップする（左上の隅にある場合のみ。
  ゲーム内ダイアログの「閉じる」は中央付近なので誤爆しない）
- **ストアのシート**: 広告の上にPlayのシートが開く（勝手に開くこともある）。シートの×（約 93%, 23%）で閉じて広告に戻る

安全設計: 押すのは上記の隅の座標だけ。中央の「インストール／開く」は絶対に押さない。
ストア処理は広告の監視中だけ。想定外が続く場合は自動で止まり、ログに残る。

## インストール後の設定

1. アプリ「広告クローザー」を開く
2. 「① ユーザー補助の設定を開く」→「広告クローザー」をオン
3. 「② ほかのアプリの上に表示する許可」をオン
4. 「フローティングボタンの表示／非表示」でボタンを出す（手動開始用。任意）
5. セルサバイバーで普通に広告を見る

## ビルド

GitHub Actions（`.github/workflows/build-apk.yml`）が `main` への push で
デバッグAPKをビルドし、リリースに `app-debug.apk` を添付します。
スマホからはリリースページからAPKをダウンロードしてインストールできます
（提供元不明アプリの許可が必要）。

## 既知の限界

- 動画広告の再生中は画面に特徴的な文字がないため、開始検知は
  エンドカード表示か広告用アクティビティの出現に頼ります。
  検知できない広告では、フローティングボタンの「広告開始」を押してください
- （v0.5で解消）フローティングボタンは「≡ 移動」部分を掴んでドラッグ移動でき、
  位置は保存される。右上の ✕ で消せて、履歴からアプリを消す（タスクキル）と連動して消える

## 署名について（v0.3〜）

CI は実行のたびに新しいマシンで走るため、そのままではデバッグ署名が毎回変わり、
Android に「既存のパッケージと競合する」と言われて上書き更新できませんでした
（v0.2 のインストール時に実際に発生）。v0.3 からは、プロジェクト固定の署名鍵
（標準の Android デバッグ鍵の形式。`debug-keystore.b64` をビルド時に復号して使用）
で毎回署名するので、今後は上書きインストールで更新できます。
なお v0.3 自体は署名が変わるため、v0.1/v0.2 からの移行時だけ一度アンインストールが必要です。

## v0.2 での修正（実機ログ 2026-11-11 に基づく）

- v0.1 は全画面ストアからの復帰で、履歴画面の「セルサバイバー」という
  アプリ名ラベルを約0.7秒ごとにタップし続けていた。One UI ではラベル部分の
  タップは無効なため約40回空振りし、ユーザーが履歴画面に置き去りになった。
- v0.2 は起動インテントでゲームを直接前面化する方式を主とし、履歴は
  「開く→中央カードを1回だけタップ」の予備手段に変更。各手順は1回だけ実行し、
  駄目なら無限リトライせずログに残して手動復帰を促す
